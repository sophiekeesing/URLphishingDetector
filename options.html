settings & privacy

chick-check checks every page you open. Most of that happens on your device. The three lookups below are already on, because protection you have to switch on protects almost nobody — but each sends a small amount of data to a third party, so here is exactly what, and how to turn any of them off.

They run on the legitimate interest in security (GDPR Art. 6(1)(f), Recital 49). Every one can be turned off and the on-device checks keep working without them. Full detail in the privacy policy.

Some lookups can't run. The browser's permission for has been switched off, so those checks are skipped. That can happen in about:addons (Firefox) or under Site access in chrome://extensions.

Sends only 4-byte hashed fragments of the page's host and path to safebrowsing.googleapis.com — never the address itself, and never the query string. Google returns a bucket of candidates; the exact match is finished on your device. Requires a free API key.

  1. Enable the Safe Browsing API in Google Cloud Console.
  2. Create an API key under APIs & Services → Credentials.

Sends the hostname only (not the path or query) to two public DNS-over-HTTPS resolvers — cloudflare-dns.com and dns.quad9.net — and compares their answers. These resolvers are independent controllers with their own privacy policies (Cloudflare, Quad9).

Looks up when the domain was first registered, using the public RDAP service each registry runs (the official replacement for WHOIS — free, no account). Phishing domains are usually days old; the sites they imitate are years old, so this catches imitations of brands the built-in list has never heard of.

Sends only the registrable domain (example.com — not the subdomain, path or query) to that TLD's own registry. Covers .com, .net, .org, .info, .xyz, .top, .online, .shop, .uk and others. Many country domains (.lv, .de, .io) publish no RDAP at all — those are reported as unavailable and never count against a site.

Shows a warning page instead of loading anything, with a Continue anyway button if you disagree. This is the only setting that helps against link trackers (Grabify, IPLogger and the like): those record your IP address, rough location and device the moment the request is sent, so a warning that arrives after the page loads is already too late.

Needs permission to see the addresses you navigate to (webNavigation on all sites) — the browser will ask. Nothing about your browsing is stored or sent; the decision is made on your device from the address alone.

Short links and unknown redirectors (bit.ly/…, ej.uz/…). This is what defeats chaining — putting a tracker behind an innocent-looking short link so there is nothing left in the address to inspect. Checking where such a link leads would mean sending the request, which is the very thing that records you, so the only real defence is to stop first and let you decide. Expect this to fire on ordinary short links too; that is the trade.

Shows a verdict on the toolbar badge for every page as you open it. Turn it off to keep chick-check strictly on-demand — the popup and the right-click check still work.

On these sites chick-check shows a grey II badge, sends nothing online and does not block. You can still check them from the popup or with a right-click. Links that send you on from an excluded site to somewhere else are still checked.

    Keeps the list in your browser account so it follows you to your other devices — Chrome and Edge sync, or Firefox Sync with Add-ons ticked. It passes through Google's or Mozilla's sync servers, never ours. Off: the list stays in this browser only. Turn everything off below does not delete it.

    Right-click a link (or select an address and right-click) and pick Check this link with chick-check. The verdict appears as a card on the page — so you can check a link before you click it, which is the only moment that helps against a tracker. Always on; nothing to configure.

    Stored in the browser's synced extension storage: your settings and API key only. Chrome and Edge sync it through your browser account; Firefox Sync does too, but only when Add-ons is ticked in its sync settings. No browsing history, no analytics, no telemetry. A 30-minute cache of recent verdicts is kept in memory to avoid repeat lookups and is cleared when the browser closes.

    Private windows: chick-check only runs there if you allow it — in Firefox under about:addons → chick-check → Run in Private Windows, in Chrome and Edge with Allow in Incognito / Allow in InPrivate on the extensions page.
